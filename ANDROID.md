# План Android-клиента SVOI

APK в 0.4.0-prebeta.1 нет. Windows EXE и WebView2 нельзя просто перепаковать в APK.

## Предлагаемая архитектура

Kotlin + Jetpack Compose для интерфейса; Android VpnService для VPN; Xray как библиотека через официальный libXray. Парсер подписок, общий формат профиля и построение конфигураций из Go вынести из package main в независимый пакет. Windows-реестр, процессы, установщик и WinDivert в Android не включать.

## Порядок работ

1. Выделить Go-пакеты subscription/profile/config без desktop API и повторно использовать существующие тесты импорта и сохранения маршрутов.
2. Сделать минимальный Android-проект и закрепить версии SDK, NDK и libXray. Сначала arm64-v8a; x86_64 для эмулятора. Проверить совместимость native-библиотек с размером страницы 16 КБ.
3. Реализовать VpnService: системное согласие через prepare(), foreground-уведомление с отключением, создание TUN, передача дескриптора ядру и корректное закрытие при revoke/stop. Сокеты ядра исключать из туннеля через protect(), иначе возможен цикл.
4. Подключить импорт ссылки, файла .svoi, просмотр конфигурации и обновление подписок. Хранить данные в приватном каталоге приложения; ключ шифрования — Android Keystore. Не выдавать локальный HTTP API другим приложениям.
5. Выбор приложений реализовать по package name через VpnService.Builder.addAllowedApplication() либо addDisallowedApplication(). Эти списки нельзя использовать одновременно. Это отдельная реализация, а не перенос Windows EXE-имён.
6. Проверить Wi-Fi ↔ мобильную сеть, сон, foreground/background, IPv4/IPv6, DNS, QUIC, разрыв сети и завершение процесса. Проверить полные подписки с loopback/balancers и фактический выход выбранных приложений.
7. Подписать APK постоянным ключом; хранить ключ вне репозитория. Для GitHub-дистрибуции — установка обновления через системный установщик по согласию пользователя. Для магазина — его механизм обновлений. Windows setup.exe на Android не используется.

## Критерий первой рабочей APK

Импорт того же .svoi, сохранение маршрутов подписки, устойчивое соединение после смены сети, выбор приложений и чистое отключение. Отдельно нужны проверка на реальном телефоне и политика обработки данных перед публикацией в магазине. Сроки и готовность APK не заявляются до этого прототипа.

## Первичные источники

- [Android VPN guide](https://developer.android.com/develop/connectivity/vpn): VpnService, согласие пользователя и foreground lifecycle.
- [VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder): списки приложений и параметры интерфейса.
- [XTLS/libXray](https://github.com/XTLS/libXray): библиотечная обёртка Xray для платформенных клиентов.
- [Xray TUN](https://xtls.github.io/config/inbounds/tun.html): внешний дескриптор TUN для мобильных платформ.
