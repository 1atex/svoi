# SVOI 0.4.0-prebeta.1 — Windows Xray client

Независимый VPN-конфигуратор с отдельным окном Windows, ядром Xray, импортом подписок и общими профилями групп. Код INCY не используется. Реализован Windows-клиент; APK и IPA пока отсутствуют.

## Перенос профиля без сервера

На первом ПК нажмите «Поделиться профилем» → «Копировать код» или «Сохранить .svoi». Передайте получателю код или файл лично. На втором ПК установите SVOI 0.4.0-prebeta.1, выберите «Получить профиль», вставьте код / выберите файл, проверьте состав и нажмите «Добавить профиль».

Переносятся одинаковые HWID, OS, Model, Locale, User-Agent и ссылки подписок. После подтверждения принимающий ПК загружает свежие конфигурации с этими заголовками. Кэш конфигураций HTTPS-подписок не передаётся; кэш в старых кодах prebeta.2 игнорируется новым клиентом. Для источников без URL переносятся готовые конфигурации, включая полные графы Xray. Предпросмотр не делает внешних запросов. Старые профили получателя сохраняются при выборе «Добавить». При неудачной загрузке ссылки остаются сохранёнными; доступны повтор и остановка загрузки. У каждой копии собственный локальный токен управления, токены отправителя и список его устройств не передаются.

Код многоразовый, без срока действия и содержит секреты подписок; это не одноразовое приглашение. Для изменения общего профиля передайте новый код. В разделе «Перенос» → «Получить профиль» можно явно заменить текущий профиль с подтверждением; активное VPN-соединение применит изменения после переподключения. Автосинхронизации, общего списка устройств и удалённого отзыва копий без сервиса нет. Формат сжат, но не зашифрован: передавайте его через доверенный канал. Максимум: 8 МБ распакованных данных, 32 источника.

Старые короткие инвайты не подходят для независимых экземпляров SVOI. Создайте новый переносимый код. Для приложения на телефоне по-прежнему нужен нативный клиент, APK/IPA в этой сборке нет.

## Что нового в 0.4

- Нейтральный Dark UI: подключение на главной, подписки и пинг в «Серверах», отдельные разделы приложений, zapret и настроек.
- Обновление HTTPS-подписок при входе (можно выключить). До двух источников одновременно; прежний список сохраняется при ошибке.
- До четырёх HTTPS-проверок серверов одновременно, ограничение одной проверки — 15 секунд. Это проверка через Xray, не ICMP-пинг.
- Автоматическая проверка и загрузка обновлений из [GitHub Releases](https://github.com/1atex/svoi/releases). Установка — по кнопке в настройках, после отключения VPN и закрытия окна. SHA-256 и размер сверяются с метаданными GitHub; скачанный файл повторно проверяется перед запуском. Authenticode-подписи SVOI пока нет.
- В TUN: «все», «только выбранные», «все кроме выбранных» приложений по имени EXE или полному пути. Регистр учитывается. После сохранения переподключитесь. Трафик, направленный в VPN, далее следует правилам подписки, включая direct; общий DNS проходит через профиль. Это не kill switch. Полные профили с routing.script несовместимы с этим режимом.
- Управление локальной копией [Flowseal zapret](https://github.com/Flowseal/zapret-discord-youtube): подключение папки, выбор general*.bat, запуск/остановка winws и журнал. BAT не выполняется: из пресета читаются аргументы. Неизвестные переменные отклоняются. Нужен администратор, игровой фильтр выключен; TUN и управляемый zapret запускаются отдельно. zapret не включён в установщик.
- Меньше фоновой работы: журнал загружается по запросу, опрос статуса замедляется в простое и прекращается в скрытой вкладке, список серверов не дублируется на главной, поиск имеет задержку ввода.

Предыдущую версию 0.3 нужно один раз обновить установщиком вручную. Начиная с 0.4 приложение получает следующие релизы само. Устройство должно иметь доступ к GitHub. Prebeta получает новые prebeta и стабильные версии; стабильные сборки пропускают prerelease.

### Обновление с 0.2.x

Отключите VPN и закройте старое окно SVOI, затем распакуйте новый архив в отдельную папку и запустите его `svoi.exe`. Иначе повторный запуск откроет прежний работающий экземпляр. Данные сохраняются в `%APPDATA%\SVOI`; перед первым запуском prebeta сохраните копию `groups.json` для возможного отката. Новый формат нескольких подписок не предназначен для старых версий приложения.

## Запуск

Рекомендуемый вариант: запустите `SVOI-0.4.0-prebeta.1-windows-x64-setup.exe`. Он устанавливает приложение вместе с ядром и создаёт ярлыки в меню «Пуск» и на рабочем столе. Права администратора для установки не требуются; файлы размещаются в `%LOCALAPPDATA%\Programs\SVOI`. Если WebView2 отсутствует, установщик скачает его с серверов Microsoft (нужен интернет). При наличии WebView2 установка работает без сети. Перед обновлением отключите VPN и закройте все экземпляры SVOI. Данные `%APPDATA%\SVOI` сохраняются при обновлении и удалении приложения. Для TUN откройте меню ярлыка → «Запуск от имени администратора».

Переносной вариант без установки:

1. Распакуйте весь Windows-архив, сохранив папку `core` рядом с `svoi.exe`. Одного EXE недостаточно: без `core/xray.exe` подключение и пинг недоступны.
2. Запустите START.cmd или svoi.exe. Нужен Microsoft Edge WebView2 Runtime.
3. Создайте личную группу. В существующей группе вход сохраняется.
4. Нажмите «Добавить подписку» для HTTPS-подписки или «Импорт из файла или текста» для конфигурации.
5. Выберите сервер, режим и нажмите «Подключить». Приложение проверяет конфигурацию настоящим Xray, запускает его и делает запрос через выбранный прокси.
6. «Связь проверена» означает успешный HTTP-запрос через Xray. «Xray запущен» означает только запуск ядра. «Нет связи» — проверка не прошла. Журнал доступен рядом с кнопкой проверки.

Готовой подписки или VPN-сервера в комплекте нет: нужны ваши рабочие конфигурации.

Повторный запуск открывает существующее окно. При закрытии основного окна Xray останавливается. Браузерный интерфейс того же процесса: http://127.0.0.1:8787. Входы браузера и окна сохраняются отдельно.

## Режимы

| Режим | Поведение |
|---|---|
| Системный прокси Windows | Прокси текущего пользователя для программ, использующих системные настройки. Это не перехват всего трафика. Предыдущие значения сохраняются и восстанавливаются при отключении. |
| Локальный SOCKS5 / HTTP | Порты только на 127.0.0.1; номера в интерфейсе. Укажите их в нужной программе. Настройки Windows не меняются. |
| TUN | Встроенный TUN Xray и core/wintun.dll: виртуальный адаптер и IPv4/IPv6-маршруты. Нужен запуск SVOI от администратора. Экспериментальный режим. Совместимость с zapret/WinDivert пока не устранена: в проверке пользователя TUN заработал после остановки zapret. |

Для системного прокси есть отдельный процесс восстановления после аварийного выхода SVOI. Xray привязан к Windows Job Object и завершается при выходе родителя. Если другой клиент изменил адрес прокси, SVOI не перезаписывает его настройки. Kill switch отсутствует: после отключения восстанавливается обычная сеть.

Проверка связи использует https://www.gstatic.com/generate_204. В TUN запрос идёт через системную маршрутизацию, в остальных режимах — через HTTP-вход Xray. Недоступность этого адреса может вызвать ошибку даже при доступном VPN-сервере.

В 0.2.2 DNS-запросы из TUN направляются в DNS-модуль Xray: применяются hosts, queryStrategy и DNS-серверы профиля. Запросы резолвера получают отдельный тег и следуют входным маршрутам профиля; существующие явные DNS-теги сохраняются. IPv4/IPv6-трафик по-прежнему захватывается адаптером.

## Импорт

- HTTPS-подписка: загрузка с общими x-hwid, x-device-os, x-device-model, x-device-locale и User-Agent, разбор и сохранение серверов.
- URI-списки, Base64, отдельные vless://, vmess://, trojan://, ss://, socks:// и http://.
- VLESS Reality / TLS, TCP, WebSocket, gRPC, XHTTP, HTTPUpgrade.
- Xray JSON с outbounds импортируется целым профилем: сохраняются все выходы, включая loopback, их теги, routing/balancers, DNS, policy, stats и observatory/burstObservatory. Один объект массива — один профиль. Разные маршруты с одинаковым первым узлом не объединяются. Отдельные outbound-объекты тоже поддерживаются.
- Экспорт выбранного профиля или сервера в Xray JSON. Локальные входы заменяются на SOCKS5/HTTP на 127.0.0.1 со свободными портами; исходные теги и sniffing сохраняются. TUN добавляется в правила входа профиля. Внешние пути логов заменяются журналом приложения.
- Предупреждения о неподдерживаемых строках, удаление дубликатов. Полностью неудачный импорт не стирает прежний список.

Clash YAML, Hysteria2 URI и Shadowsocks plugins пока не поддерживаются. Полные профили с API/metrics/reverse, нестандартными входами или несколькими входами одного типа отклоняются с пояснением. Сложные выходы и цепочки внутри принятого JSON проверяет Xray при запуске.

URL подписки должен использовать HTTPS и порт 443. Приватные/служебные IP блокируются при DNS-разрешении, редиректы отключены. Лимит ответа — 4 МБ, запроса — 20 секунд. Если провайдер возвращает редирект или страницу вместо конфигураций, используйте прямую ссылку или импорт файла.

## Группы

Работают одноразовые приглашения на 15 минут, до 32 устройств, отзыв участника владельцем и общий профиль запроса подписки. Фактическая платформа участника хранится отдельно.

Для централизованной группы с общим списком участников нужен общий HTTPS-сервис. Переносимый профиль из раздела выше работает без такого сервиса. 127.0.0.1 на телефоне не является адресом компьютера. Режим svoi.exe -server запускает только сервис групп, без управления Xray и сетью сервера. API ядра доступен только авторизованным локальным запросам настольного приложения. Нативный Android/iOS VPN-клиент ещё не реализован.

Общий профиль не гарантирует, что провайдер посчитает подключения одним устройством: это зависит от его серверной проверки. Отзыв участника закрывает будущие запросы к группе, но не отзывает ранее выданные VPN-ключи у провайдера.

## Данные и зависимости

- %APPDATA%\SVOI\groups.json: группы, хеши ключей доступа, URL подписок и конфиги серверов. URL и VPN-ключи хранятся в открытом виде; не публикуйте файл.
- %APPDATA%\SVOI\runtime: временные конфиги Xray и снимки для восстановления прокси. Конфиг удаляется при остановке ядра.
- %APPDATA%\SVOI\WebView2: профиль окна. Вход хранится в localStorage. Восстановление потерянного входа владельца пока не реализовано.
- Параметр -data C:\path\groups.json переопределяет файл состояния.
- core/xray.exe: официальный Xray 26.10.21, MPL-2.0. Источник, SHA256 архива и ссылка на исходники — core/SOURCE.txt. Лицензии Xray/Wintun — в core, зависимости Go — в licenses.

## Сборка и проверка

Нужен Go 1.26+. После клонирования выполните `./prepare-core.ps1`: он загрузит закреплённый официальный Xray и проверит SHA-256. Интерфейс встроен в EXE: после изменения нужна пересборка. Зависимости закреплены в go.mod/go.sum. Ядро распространяется отдельно в папке core.

Закройте приложение перед сборкой:

    go test ./... -count=1
    go vet ./...
    .\build-resources.ps1
    go build -trimpath -ldflags '-H windowsgui' -o svoi.exe .

`run.ps1` генерирует ресурсы, собирает и запускает приложение. `build-resources.ps1` использует закреплённый go-winres v0.3.3 для ICO, версии и манифеста Windows. Генерируемый `rsrc_windows_amd64.syso` не хранится в исходном архиве. Иконка и исходный PNG находятся в `assets`, описание генерации — `assets/GENERATION.txt`.

`package.ps1` проверяет проект и создаёт установщик, переносной Windows-архив, исходники, ICO и SHA256SUMS. Для установщика нужен Inno Setup 6.4+; нестандартный путь передаётся через `-IsccPath`. WebView2 bootstrapper загружается с Microsoft и проверяется по Authenticode перед упаковкой. `-SkipInstaller` собирает только ZIP и ICO. Скрипт установки находится в `installer/svoi.iss`; состав пакета формируется из явного списка, пользовательские данные в него не входят.

`installer/test-setup.ps1` проверяет установку, повторную установку, совпадение файлов с ZIP, ярлыки, запись удаления и удаление с сохранением постороннего файла. Он использует тот же сценарий и содержимое релиза, но отдельные AppId, mutex и каталог `dist/setup-test-*`, чтобы не затрагивать рабочую установку. Журналы остаются в тестовом каталоге. Проверка требует уже установленный WebView2; ветка загрузки на чистой Windows проверяется отдельно.

Тесты проверяют права и изоляцию групп, одинаковые заголовки подписки, обработку ответов, импорт/сохранение серверов и отсутствие VPN-ключей в кратких API-ответах. При наличии core/xray.exe они также запускают настоящее ядро: проверяют конфиги Reality/WS/gRPC/XHTTP/VMess/Trojan/Shadowsocks, передают HTTP и SOCKS5-трафик через локальный VLESS-сервер, проверяют остановку и уборку после принудительного завершения. Без ядра интеграционные тесты пропускаются.

Автотесты не меняют системные настройки Windows и TUN-маршруты. Тест аварийного восстановления проверяет вызов обработчика и освобождение ресурсов, а не фактическое восстановление реестра. В версии 0.2.1 добавлены проверки сохранения графа полного профиля и передача трафика через два балансировщика и loopback. Для локальной проверки своей подписки без подключения установите SVOI_VALIDATE_SUBSCRIPTION в путь JSON и выполните go test -run TestLocalSubscriptionProfiles -v. После обновления с 0.2 обновите подписку, чтобы заменить ранее извлечённые узлы полными профилями.

## Дополнительные API 0.2

Все методы требуют Authorization: Bearer <ключ устройства>.

| Метод | Путь | Действие |
|---|---|---|

| POST | /api/subscription/import | Импорт {content}; владелец |
| POST | /api/subscription/refresh?id={id} | Обновить только указанный источник |

| GET | /api/connection | Состояние и журнал |

API групп, устройств, приглашений и профиля сохранены.

Версия 0.4.0-prebeta.1: на главной отображается полный список профилей. Флаги из названий (эмодзи или ISO-коды NL, [NL], nl и т. п.) отображаются встроенными SVG из flag-icons 7.6.0, MIT. Изображения работают без подключения к CDN. Поиск поддерживает код и русское название страны.

## Выпуск следующей версии

1. Обновите appVersion в main.go и номер в web/index.html, затем RELEASE-NOTES.md.
2. Выполните ./package.ps1. Артефакты появятся в releases/vVERSION.
3. Закоммитьте исходники и отправьте тег vVERSION. Workflow .github/workflows/release.yml проверит версию, соберёт Windows-пакеты и опубликует GitHub Release. Ручной запуск workflow только собирает артефакт.
4. Не переиспользуйте опубликованные версии. Имя установщика должно быть SVOI-VERSION-windows-x64-setup.exe, а asset должен иметь digest sha256 в GitHub API. Только после публикации корректного asset клиент предложит обновление.

Источник закреплён как 1atex/svoi в updater.go. Форки могут изменить releaseRepository при сборке. Данные пользователя, runtime-конфиги, подписки и ключи не должны попадать в репозиторий или релиз.

Настройки этого компьютера хранятся рядом с groups.json в groups.json.settings.json и не передаются кодом профиля. Проект SVOI распространяется по MIT; лицензии сторонних компонентов сохранены отдельно. План Android находится в [ANDROID.md](ANDROID.md).
