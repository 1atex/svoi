# Производительность Android

## Сравнение архитектуры, 24 октября 2026

Исследован предоставленный APK INCY 3.8.1 (`llc.itdev.incy`), SHA-256 `67c8253b3dc5fd2a0a0b27d5d4736834fa43e276a1a54d3282f5df0935092836`. Выводы относятся к статическому анализу manifest, состава библиотек и DEX этого файла. Код и бинарники INCY в репозиторий не добавляются. Реальное потребление ресурсов INCY не измерено: APK содержит ARM64/ARMv7, наш тестовый эмулятор — x86_64.

| Механизм | Наблюдение в APK | SVOI |
| --- | --- | --- |
| Обработка TUN | В `IncyCore` две ветки: `startXrayWithTunFd` и Xray + HEV SOCKS5. Наличие HEV не означает, что всегда выбран именно он. | Прямой Android TUN Xray, без дополнительного SOCKS-перехода. Само наличие этой схемы не доказывает преимущества по скорости. |
| Процесс VPN | `IncyVpnService`, `ProxyOnlyService`, `IncyCoreService` объявлены в процессе `:vpn`. | В Preview 5 Go, хранилище, проверки и VPN перенесены в `:vpn`. Flutter обращается к службе через Binder. |
| Память Go | Вызовы ограничения памяти и настройки GC. Найдены режимы GC=50 с лимитом и GC=100 без лимита. | Стандартные настройки Go. Уменьшение порога GC без замеров может увеличить CPU и расход батареи. |
| Завершение | Перед запуском очищается прежний движок; для HEV предусмотрены отдельная остановка и ограниченное ожидание. | Последовательная очередь start/stop, закрытие Xray и Android TUN-дескриптора. В закреплённой версии Xray ядро читает дубликат FD, оригинал остаётся у приложения. |
| HEV | В генераторе конфигурации — MTU по умолчанию 1500, стек задачи 86016 байт, connect timeout 5 с, error-only журнал. | MTU 1500; дополнительный HEV не включён. Переносить его размеры буферов на другой стек нельзя. |

В build info `libgojni.so` указаны Go 1.27.2 и Xray commit `1b1647cd9ddf0abc34b981d4611fc03bcac1ca74` — тот же upstream-коммит, что закреплён у SVOI. При этом модуль Xray заменён локальным каталогом при сборке INCY, поэтому метаданные не доказывают отсутствие дополнительных патчей или идентичность бинарников.

## Исправления Preview 4

1. Разделены release ARM64 APK для устройств и debug APK для эмулятора. Flutter debug оптимизирован под разработку; сравнивать его с релизным INCY некорректно. Release-сборка пока подписывается временным ключом CI.
2. Убраны фоновые опросы UI (раньше до четырёх запросов в минуту при работающем VPN). Native foreground service сохраняет соединение независимо от UI.
3. Лимит временных экземпляров Xray для пинга уменьшен с четырёх до двух; при системном признаке `ActivityManager.isLowRamDevice` используется один слот. Общее время большой очереди недоступных серверов может вырасти; пиковая параллельная работа уменьшена.
4. Отмена пинга проходит Dart → Kotlin → Go. Xray получает исходный отменяемый контекст проверки, а не контекст DialContext, от которого HTTP transport отделяет отмену. Тест проверяет закрытие удалённого HTTP-соединения, а не только исчезновение индикатора.
5. На Android отключён access log каждого соединения; warning/error остаются. Конфигурация маршрутов, DNS и балансировщиков сохранена.
6. Один HTTP-handler на MobileApp вместо создания mux на каждый внутренний запрос.

Микробенчмарк `go test ./backend -run '^$' -bench BenchmarkMobileRequest -benchmem -count=3`, Windows/amd64, Ryzen 5 5600X, Go 1.27.3:

| Локальный запрос `/api/health` | До | После |
| --- | --- | --- |
| Выделений памяти | 100 | 69 |
| Байт на запрос | 10587–10588 | 8794 |
| Время | 12.7–13.8 мкс | 8.3–9.3 мкс |

Это только накладные расходы локального API. По этим цифрам нельзя делать вывод о скорости туннеля, общем RSS приложения или автономности Android.

## Следующие измерения

CI сохраняет ресурсные снимки debug-эмулятора в `android-test-results/svoi-android-resources.log`: PSS, накопленное процессорное время, потоки и FD до подключения и после трёх циклов. Их следует сравнивать на одинаковом API/ABI и сборке. Накопленное CPU time не является процентом нагрузки. PSS после разрыва может не сразу снижаться из-за GC и кешей.

Первый [успешный прогон Preview 4](https://github.com/1atex/svoi/actions/runs/40114101021), Android 10 x86_64, debug, один тестовый VLESS-профиль:

| Состояние | PSS, КиБ | Потоки | FD |
| --- | ---: | ---: | ---: |
| После инициализации | 340816 | 39 | 89 |
| Первое подключение | 358271 | 43 | 97 |
| После отключения 1 | 361692 | 45 | 92 |
| После отключения 2 | 362264 | 46 | 93 |
| После отключения 3 | 362400 | 47 | 94 |

PSS после прогрева почти стабилен в этом коротком тесте, но потоки и FD ещё растут. Трёх циклов недостаточно, чтобы отличить прогрев runtime/HTTP-клиента теста от утечки: необходим продолжительный прогон с паузами и классификацией дескрипторов. Эти числа включают Flutter debug и тестовую инфраструктуру; это не память релизного ядра и не сравнение с INCY. Release ARM64 APK собран успешно (59.6 MB по выводу Flutter), но его PSS на физическом телефоне пока не измерен.

Для решения о смене TUN нужны одинаковые сервер, профиль и маршрутизация, release-сборки на одном ARM64-устройстве: простой 10 минут, фиксированная TCP/UDP-нагрузка, 20 переподключений, выключенный экран, смена Wi-Fi/мобильной сети. Сравнить скорость, CPU, PSS после прогрева, FD и расход энергии. До таких измерений преимущество HEV или прямого Xray TUN не установлено.

Следующий архитектурный кандидат — отдельный VPN-процесс с Binder IPC. Он позволит освобождать UI независимо от VPN, но добавит второй процесс и потребует корректного управления хранилищем, статусом и жизненным циклом. В Preview 4 этот перенос не выполнен. Произвольный жёсткий лимит памяти, принудительный GC по таймеру и постоянный wake lock не добавлялись.

Первичные справочные материалы: [Flutter build modes](https://docs.flutter.dev/testing/build-modes), [Android VPN lifecycle](https://developer.android.com/develop/connectivity/vpn), [HEV SOCKS5 tunnel](https://github.com/heiher/hev-socks5-tunnel). Анализ использования этих механизмов в INCY основан на локальном APK, а не на документации HEV.

## Изоляция службы в Preview 5

Go и хранилище имеют одного владельца — службу в процессе `:vpn`. UI не загружает JNI-библиотеку и не создаёт второй экземпляр Go. Запросы Binder выполняются в рабочих потоках; большие профили передаются через ограниченные по размеру pipe-дескрипторы. Закрытие клиента отменяет его проверки серверов. После падения службы клиент переподключается, но не повторяет команды изменения данных автоматически.

Инструментальный тест проверяет отдельный PID, отсутствие `libgojni.so` в UI, передачу 2 МиБ в обе стороны, 20 циклов TUN с реальным HTTP-трафиком через тестовый VLESS-сервер, закрытие и повторное создание Activity при активном VPN, аварийное завершение процесса службы и восстановление сохранённых профилей. Это закрытие Activity, а не уничтожение процесса UI.

Ресурсные снимки теперь относятся только к процессу службы: PSS, CPU time, потоки, FD по типам, Go heap, goroutines и GC count. Их нельзя напрямую сравнивать с общей памятью Preview 4, включавшей Flutter. Тест проверяет отсутствие TUN FD после остановки и ограниченный рост FD/goroutines после прогрева. Результаты прогона добавляются после выполнения CI; наличие теста само по себе не подтверждает прохождение.

Изоляция позволяет Android освобождать UI независимо от VPN, но добавляет IPC и второй процесс. Снижение общей памяти, расхода батареи или улучшение скорости пока не заявляется.
