# Night Island для Windows

SVOI: настройки → Интеграции → «Разрешить управление из Night Island». Сначала в Night Island нужно выбрать настройки → Интеграции → VPN → SVOI. SVOI показывает путь к запрашивающему EXE; разрешение привязывается к его пути, SHA-256 и пользователю Windows. После замены сборки Island разрешение нужно выдать заново.

Разрешение выключено по умолчанию. Оно хранится отдельно от профиля в защищённом Windows DPAPI файле `groups.json.night-island`. Экспорт подписок и настроек его не переносит. Выключение разрешения закрывает текущие каналы клиента и запрещает новые команды, в том числе ожидающие сетевой блокировки. Начатое до отзыва подключение не отключается автоматически.

Канал `\\.\pipe\SVOI.NightIsland.v1.<SID>` принимает только локальные процессы того же пользователя Windows; удалённые клиенты запрещены. Путь и PID клиента берутся из Windows, а не из запроса. Проверяется отпечаток EXE. Доступны только `state`, `favorites`, `connect`, `switch` по ID и `disconnect`. Ответ содержит состояние ядра, активный/выбранный сервер, избранные, режим и результат фактической проверки связи. В ответ не входят URL подписок, конфигурации, HWID, внутренний ключ backend, порты или журнал ядра.

Команды используют существующий `engineAPI`, включая выбор ядра, маршрутизацию и проверки WARP/zapret. Нажатие подключения в Island запускает последний выбранный доступный сервер SVOI. Смена в работающем SVOI отражается в Island; обратная смена обновляет выбор Flutter-клиента. Проверка связи выполняется после запуска тем же ядром.

Проверки: `go test -tags native_core ./backend -run 'TestIsland|TestNativeBackendCapability'`, `flutter test`, а также `python tests/night-island-windows.py <папка-сборки-SVOI> <NightIsland.exe> --fixture-dir <каталог-в-.ui-preview>`. Скрипт использует настоящие Windows EXE и Xray/VLESS между локальными точками; внешние подписки и системные маршруты не меняются.

В этой работе проверены двойная команда, переключение избранного, фактически активный сервер при ошибке валидации, смена из SVOI, отключение, закрытие/перезапуск, отзыв доступа и отказ другой сборке клиента. Внешняя VPN-подписка не использовалась. Полная визуальная проверка окон и живое подключение Happ остаются ручной проверкой: Computer Use не запустился с ошибкой `failed to write kernel assets`. Модуль Happ и миграция/экспорт выбора провайдера покрыты регрессионными тестами Island.
